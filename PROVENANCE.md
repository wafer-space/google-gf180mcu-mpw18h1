# Provenance of Google MPW-18H1

MPW-18H1 was a private four-project GF180MCU test shuttle that Google ran on GlobalFoundries' private MPW service (GF's 18H1 run), not an Efabless Open MPW shuttle. The designs were submitted in February and March 2023 and the final dies committed in December 2023, in the same form as the Open MPW shuttles: Caravel dies, an Efabless-style `tapeout/` directory in each slot repository and Efabless-style project IDs. Every project is a [Caravel](https://github.com/efabless/caravel-gf180mcu) die: the user design in `user_project_wrapper`, surrounded by the same management SoC, padframe and power routing on every die.

# How This Repository Was Generated

This repository presents the shuttle in the same format as the [wafer.space](https://wafer.space/) run repositories ([ws-run1](https://github.com/wafer-space/ws-run1), [ws-run2](https://github.com/wafer-space/ws-run2)), so the same tools can analyse it. The reticle in `layout/` is synthetic and is not the mask set as manufactured. It was generated by the wafer.space [reticle-stitcher](https://github.com/wafer-space/reticle-stitcher), the same tool and settings as the ws-run reticles, from the individual final dies published at [https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-18h1](https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-18h1):

1. The published dies are 3890×5100 µm, but only because of their PR boundary rectangle (layer 0/0): every other shape, including the whole padframe (`chip_io`), lies within the 3880×5070 µm of a standard Caravel die, the same size as the GFMPW-0 dies, and the extra 10 µm on the right and 30 µm at the top are empty. The PR boundary layer was removed from each die, in every cell, as Efabless did for GFMPW-0 ("remove pr boundary for projects"); no other layer changed, which was checked shape by shape count and extent on every layer. The PR boundary is not a mask layer.
2. Each 3880×5070 µm die (top cell renamed `caravel`) was then put through the last two steps a wafer.space project gets from LibreLane: dummy fill (COMP, Poly2 and Metal1–5) from the gf180mcuD PDK's `fill_all.rb`, as `KLayout.Filler` does, then the wafer.space 26 µm seal ring from the PDK's `sealring.py`, as `KLayout.SealRing` does, giving a 3932×5122 µm 1×1 slot. The published dies have neither fill nor seal ring; this fill is a stand-in for whatever fill Efabless or GF added later, added so that the renders and density figures can be compared with the wafer.space runs.
3. `reticle_stitcher.py` placed the four dies from a 4×4 tile map as a 2 × 2 micro-shuttle, wrote `data/manifest.csv`, `images/GFMPW18H1.svg`, the project table in [README.md](README.md) and `images/GFMPW18H1.png` (rendered with `scripts/lay2img.py`), and added its own dummy fill to the saw streets between the dies.
4. `images/GFMPW18H1.png` and `images/GFMPW18H1.svg` were then placed, unscaled relative to each other, in the top left corner of a 30.0 × 23.379 mm canvas, the size of the ws-run1 and ws-run2 reticle images, so that the dies show at the same scale as on those runs.

Each die's top cell in the layout is `<CODE>_caravel_<column>_<row>`; the code is the last four digits of the project ID.

# Sources

- Source: the shuttle mirrors at [https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-18h1](https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-18h1): one repository per slot plus `foundry`, which holds `manifest-gfmpw-18h1.csv`.
- Each die is `tapeout/outputs/gds/caravel_<ID>.gds.gz` at the head of `main` in its slot repository; all four match the SHA1 in the manifest. (The manifest's download links all point at `slot-001`; the files are in their own slots.)
- The manifest lists the four projects as A1 to D1; here they are arranged as a 2 × 2 micro-shuttle, A1 and B1 on the top row.
- The published dies keep their PR boundary (0/0) shapes, including inside the standard cells; they were removed here (see above).
- Neither the published dies nor the GFMPW-0 dies have a seal ring: there is no seal ring marker (167/5) and no COMP, contact or Metal1 ring at the edge; COMP, contacts and Metal1 all stop about 65 µm inside the die edge.
- `SHA256` and `LAYOUT` in `data/manifest.csv` refer to the sealed die files given to the stitcher (`<CODE>/caravel.gds`), which are not published separately; the stitched layout contains them unchanged.
- Repository links point to the designer's GitHub repository where one in a public mirror contains the slot's three newest non-Efabless commits; otherwise to the slot repository at googlesource. The exception is 0004, which links to the `mpw18h1` directory of [idea-fasoc/openfasoc-tapeouts](https://github.com/idea-fasoc/openfasoc-tapeouts/tree/main/mpw18h1): the design's description, generators and GDS (it names slot-004 as its submission).
- Names and descriptions of 0001 and 0004 follow [Silicon Prawn](https://siliconprawn.org/)'s pages for the dies and the OpenFASoC tapeout README; Silicon Prawn has photographs of both (see [README.md](README.md#die-photographs)), and describes the shuttle as "not technically efabless but done by Google with the open source GF180MCU on the standard GF shuttle program". Its photograph of the Gel-Pak box of 0001's dies ([copy](https://data.wafer.space/big-storage/siliconprawn.org/efabless/package/gf180mcu-mpw18h1-18100001/pack_top.jpg)) is labelled customer GOOGLE LLC (MPW18H1), device PGSTDCELLS, wafer 5, lot 3CXY14296.1, quantity 20.
- All four slot repositories are Apache-2.0 licensed.
